## Core idea перед примерами

Лекция начинается с напоминания: core idea of `RAG` — соединить off-the-shelf `LLM` с `knowledge base` информации, к которой модель могла не иметь доступа во время training.

Многие `LLM`-powered systems реализуют именно такую модель.

## Code generation

Один важный application of `RAG` — code generation.

Хотя language models обучались на большом количестве кода, возможно даже на каждом public Git repository, правильная генерация кода для конкретного проекта требует specialized information.

Для конкретного проекта `LLM` нужно знать:

- classes;
- functions;
- definitions;
- общий стиль кода проекта.

Если построить `RAG`-систему, которая использует собственную code base как `knowledge base`, эта информация становится доступна `LLM`.

> **Процесс:** `retriever` извлекает relevant classes, definitions и files из repository, после чего `LLM` может лучше генерировать код или отвечать на вопросы, связанные с конкретным проектом.

Такой подход помогает модели учитывать не только общий синтаксис и паттерны программирования, но и детали именно данного codebase.

## Company chatbots

Другой major application — настройка chatbots под конкретную компанию.

У каждой компании есть собственные:

- products;
- policies;
- communication guidelines.

Если рассматривать enterprise documents как `knowledge base`, можно развернуть `LLM` в разных полезных сценариях.

Варианты из лекции:

- chatbot для customer service, который знает информацию о продуктах компании;
- chatbot, который учитывает current inventory;
- chatbot, который знает типовые шаги устранения неполадок;
- internal chatbot, который точно отвечает на вопросы о company policies;
- internal chatbot, который направляет пользователя к useful documentation.

В обоих случаях `knowledge base` помогает ground responses `LLM` в конкретных продуктах или политиках компании.

> **Вывод:** company-specific `knowledge base` помогает уменьшать случаи, когда `LLM` генерирует generic или misleading responses.

## Healthcare и legal domains

`RAG` имеет significant applications в healthcare и legal domains.

В таких сценариях `knowledge base` может содержать:

- юридические документы из конкретного дела;
- тексты из недавно опубликованных медицинских журналов;
- другие специализированные документы соответствующей области.

Эти области выделяются двумя свойствами:

- precision is imperative;
- объем нишевой и потенциально private information очень велик.

Поэтому `RAG`-based approach может быть единственным способом развернуть `LLM`-based product, который одновременно:

- достаточно accurate;
- использует private information.

## AI-assisted web search

Еще одно major application — AI-assisted web search.

Исторически search engines работали как `retriever`: получая search query, они возвращали relevant websites.

Современные search engines могут дополнительно предоставлять AI summaries of search results. Такие summaries быстро показывают наиболее useful information в skimmable форме.

> **Определение:** AI web summaries в лекции описаны как `RAG`-система, у которой `knowledge base` — весь Internet.

В этом примере `retriever` — это механизм поиска web pages, а `LLM`-часть создает сжатое summary найденных результатов.

## Personalized assistants

Лекция подчеркивает, что `RAG` полезен не только в large-scale системах. Сильно персонализированные системы тоже могут быть эффективными.

Personalized assistants в разных инструментах могут помогать:

- отправлять messages;
- организовывать schedule;
- drafting documents;
- completing projects big and small.

Такие assistants могут находиться в:

- text messages;
- email client;
- word processor;
- calendar;
- других рабочих инструментах.

В этих случаях качество поддержки зависит от того, сколько context `LLM` имеет о текущем project или задаче.

`knowledge base` может быть относительно небольшой, например:

- text messages;
- contact lists;
- emails;
- folder of documents.

Но эти документы насыщены важным context. Поэтому `RAG`-система с доступом к personal information малого масштаба может выполнять задачи существенно более релевантно для конкретной ситуации пользователя.

## Общее условие для полезного RAG

Лекция формулирует общий принцип: у многих companies, organizations и individual users есть collections of information, которые можно использовать для повышения качества text generated by an `LLM`.

> **Вывод:** если у вас есть доступ к информации, которая, вероятно, не использовалась для training `LLM`, есть потенциал построить полезное `RAG` application.

В некоторых случаях `RAG` может даже позволить использовать `LLM` там, где это иначе было бы impossible.

## Итог лекции

`RAG` применим в широком наборе контекстов:

- code generation для конкретного проекта;
- enterprise customer service и внутренние chatbots;
- healthcare и legal applications;
- AI-assisted web search;
- personalized assistants.

Общая причина полезности одинакова: `RAG` дает `LLM` доступ к релевантной информации, которой модель, вероятно, не имела при training, и тем самым делает ответы более grounded, specific и accurate.
