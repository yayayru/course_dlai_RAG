Не трудно — такие датасеты есть, просто они обычно называются не «текст → документы», а information retrieval / passage retrieval / question–passage relevance datasets.

Для RAG тебе нужен примерно такой формат:

query:
"How does Python garbage collection work?"

positive passages:
- chunk_17
- chunk_42

negative passages:
- chunk_9
- chunk_103

или:

query_id | doc_id | relevance
q1       | d17    | 1
q1       | d42    | 1
q1       | d9     | 0

Самые известные варианты — MS MARCO, BEIR, Natural Questions, HotpotQA, DPR datasets. У них уже есть запросы и релевантные passages/documents, поэтому можно честно считать Precision@K, Recall@K, MRR, nDCG.

Для твоей учебной задачи я бы особенно рекомендовал BEIR: это не один датасет, а набор retrieval-бенчмарков с достаточно удобной структурой:

corpus
  doc_id → text

queries
  query_id → query text

qrels
  query_id → relevant doc_ids

То есть почти идеально для экспериментов с retriever:

query
   ↓
embedding model
   ↓
vector DB / similarity
   ↓
Top-K doc_ids
   ↓
сравниваем с qrels
   ↓
Precision@K / Recall@K / MRR / nDCG

И это уже гораздо ближе к настоящему RAG, чем трюк с одинаковыми категориями.

Если хочешь, я могу подобрать тебе 3–5 конкретных небольших датасетов с Hugging Face, которые легко скачать и сразу использовать с sentence-transformers + FAISS/Chroma, без огромных объёмов данных.

Я бы взял SciFact первым

Он небольшой: корпус содержит примерно 5 183 научных абстракта, а запросами являются научные утверждения. Для запросов уже известны релевантные документы. 

Например, концептуально:

query:
"Vitamin D reduces the risk of ..."

              ↓

Retriever

              ↓

doc_391
doc_812
doc_127
doc_992
...

              ↓

сравниваем с ground truth

И ground truth выглядит уже не как категория:

query_id = 42

relevant_docs = {
    doc_391
}

В Hugging Face для SciFact есть отдельные qrels:

query-id | corpus-id | score
0        | 31715818  | 1
2        | 13734012  | 1
4        | 22942787  | 1
...

То есть это именно то, чего тебе не хватало в предыдущем примере: конкретный запрос связан с конкретным документом, а не просто с категорией. 

Структура BEIR в целом такая:

corpus
──────────────────────────────
doc_id → title + text


queries
──────────────────────────────
query_id → query text


qrels
──────────────────────────────
query_id → doc_id → relevance

BEIR официально использует именно corpus, queries и qrels; qrels являются разметкой релевантности между запросом и документом. 

NFCorpus тоже очень хороший вариант

Он даже меньше по корпусу — около 3 633 документов. В нём запросы связаны с biomedical/nutrition retrieval. 

У него особенно удобно демонстрировать Recall@K, потому что на запрос может приходиться много релевантных документов. В BEIR для NFCorpus указано в среднем около 38.2 relevant documents/query для соответствующего benchmark-набора. 

Получается что-то вроде:

query
"Does eating nuts reduce cardiovascular risk?"

Ground truth:

doc_14   relevant
doc_87   relevant
doc_103  relevant
doc_192  relevant
doc_441  relevant
...

Retriever вернул:

Top-5:

doc_14   ✅
doc_87   ✅
doc_999  ❌
doc_103  ✅
doc_712  ❌

И вот здесь уже естественно считаются:

\[
Precision@5 = \frac{3}{5}
\]

и

\[
Recall@5 =
\frac{3}
{\text{все релевантные документы для этого query}}
\]

Без каких-либо категорий.

У NFCorpus qrels тоже доступны непосредственно на Hugging Face в формате:

query-id | corpus-id | score



Что я бы сделал в твоём курсе

Если цель — перейти от твоего текущего примера с категориями к настоящему RAG retrieval, я бы сделал следующую лабораторную на SciFact.

Архитектура будет очень чистой:

SciFact corpus
    │
    │  5k documents
    ▼
SentenceTransformer
    │
    ▼
document embeddings
    │
    ▼
FAISS
    ▲
    │
query embedding
    │
query

На выходе:

retrieved_doc_ids = [
    "doc_31715818",
    "doc_...",
    "doc_...",
    ...
]

А потом:

predicted = retrieved_doc_ids[:k]
relevant = qrels[query_id]

precision = ...
recall = ...

И тогда ты фактически убираешь искусственную конструкцию:

query category
      ↓
document category
      ↓
same category = relevant

и переходишь к нормальной:

query_id
   ↓
qrels
   ↓
actual relevant document_ids

Именно SciFact я бы выбрал следующим шагом: он достаточно маленький, чтобы не отвлекаться на инфраструктуру, но при этом задача уже полностью настоящая retrieval-задача.

Есть датасеты на русском?

№№№

Да, есть. Для твоей задачи я бы смотрел именно на русскоязычные retrieval datasets с qrels, а не просто QA-датасеты.

Самый подходящий вариант — MIRACL Russian. В нём есть русские запросы, русский корпус Википедии и relevance judgments query_id → doc_id → relevance. Для русского языка там около 4.7 тыс. train-запросов и 1.25 тыс. dev-запросов; разметка делалась носителями языка. 

Структура там именно такая, какая тебе нужна:

query
"Какая самая высокая гора в России?"
        ↓
retriever
        ↓
doc_123
doc_874
doc_991
...
        ↓
qrels
        ↓
какие из doc_id действительно релевантны

То есть уже можно считать:

Precision@K
Recall@K
MRR
nDCG

без категорий.

Минус MIRACL — корпус русский довольно большой: около 9.5 млн passages из примерно 1.48 млн статей Википедии.  Для учебной работы я бы поэтому не индексировал его целиком, а взял небольшой subset, например 5–20 тысяч passages плюс документы, которые фигурируют в qrels.

Есть ещё очень удобный вариант — SberQuAD, преобразованный в retrieval-формат. На Hugging Face есть sberquad-retrieval-qrels: там русские запросы связаны с конкретными corpus-id, а не с категориями. Train содержит примерно 45 тыс. qrel-записей и около 9 тыс. уникальных corpus id. 

Для обучения это даже может быть лучше MIRACL:

SberQuAD retrieval
────────────────────────

query:
"Кто написал роман ...?"

       ↓

corpus

chunk_0
chunk_1
chunk_2
...
chunk_9080

       ↓

ground truth

query_100 → chunk_0
query_101 → chunk_0
query_102 → chunk_0
...

Это уже очень близко к настоящему passage retrieval в RAG.

Ещё один интересный вариант — MultiQ из русского benchmark TAPE. Это русскоязычный multi-hop QA dataset, который авторы прямо описывают как пригодный для open-domain QA, information retrieval и reading comprehension.  Он интереснее, если позже захочешь исследовать вопросы, для ответа на которые нужно найти несколько фрагментов.

И появился более свежий вариант — RusBEIR. В 2025 году были опубликованы дополнительные русские retrieval-наборы на основе русской Википедии, включая задачи для retrieval, fact-checking и RAG; там есть релевантность вплоть до уровня предложений и градуированная разметка.  Это уже особенно интересно именно с точки зрения современного RAG.

Для твоего курса я бы выбрал так:

SberQuAD retrieval → MIRACL Russian → RusBEIR.

Начни с SberQuAD retrieval, потому что он небольшой и позволит буквально заменить текущую схему

query.category == document.category

на настоящую:

qrels[query_id] → relevant corpus_ids

и почти весь твой текущий код для Precision@K и Recall@K останется концептуально тем же.

А после этого MIRACL уже покажет тебе, как такая же система ведёт себя на настоящем крупном retrieval-корпусе.
