## LLM как замечательный инструмент

`LLM` — замечательные инструменты. Они умеют отвечать на вопросы, суммировать и переписывать текст, давать обратную связь по документам, генерировать код и многое другое. Подобные задачи всего несколько лет назад казались недостижимыми для компьютеров, а взаимодействие с LLM может ощущаться как работа с другим человеком.

`RAG` — подход, который дополнительно улучшает производительность больших языковых моделей, предоставляя им доступ к информации, которую они не знают из своего обучения (training).

## Три примера вопросов

Чтобы продемонстрировать эту идею, рассматриваются три примера вопросов.

1. **«Почему отели дороже по выходным?»** На этот вопрос можно ответить, вероятно, без дополнительной информации: по выходным больше людей путешествует, поэтому выше конкуренция за номера.
2. **«Почему отели в Ванкувере (Vancouver) настолько дороги в эти ближайшие выходные?»** Для ответа нужна дополнительная информация. Если поискать в интернете, можно обнаружить, что международная суперзвезда Тейлор Свифт (Taylor Swift) находится в городе в эти выходные с двухдневной (two-night) резиденцией. С этой дополнительной информацией на вопрос снова можно ответить.
3. **«Почему в Ванкувере не хватает гостиничных номеров близко к центру города (downtown)?»** Чтобы ответить на этот вопрос, потребуется провести глубокое исследование истории развития Ванкувера, городского планирования (urban planning) в целом и так далее — то есть нужен доступ к большому количеству специализированной информации.

## Две фазы ответа на вопрос

Способ, которым отвечают на подобные вопросы, можно представить как две фазы:

1. Сначала собирается вся необходимая информация.
2. Затем происходит рассуждение (`reasoning`) над этой информацией для формирования ответа.

Как видно на примере первого вопроса, иногда не нужно собирать никакой информации — на основе имеющихся знаний о мире можно ответить сразу. В других случаях может потребоваться собрать немного информации или даже очень много.

В RAG процесс сбора полезной информации называется `retrieval` (извлечение). А процесс рассуждения над этой информацией и формирования ответа называется `generation` (генерация).

## Почему LLM выигрывают от retrieval

LLM получают пользу от стадии retrieval примерно по тем же причинам, что и люди. LLM можно представлять как что-то вроде человека, обладающего широким кругом общих знаний благодаря чтению огромных объёмов интернета. Когда LLM получает промпт, она опирается на эти знания для генерации ответа. Для многих промптов это отлично работает.

В других случаях, однако, LLM не знает информацию, которая ей нужна для точного ответа. Промпт может касаться очень недавнего события или какой-то специализированной информации, которую модель ранее не видела. Как и в случае с человеком, нереалистично ожидать, что LLM будет экспертом по каждой теме. И LLM дают гораздо лучшие ответы, когда у них есть доступ к лучшей информации.

> Признание того, что LLM тоже выигрывают от фазы retrieval, — это и есть ключевая идея RAG.

## Как LLM обучаются и почему им не хватает информации

Конечно, LLM — это не люди, которые проводят много времени на Википедии. Вместо этого это математические модели, обученные на массивных датасетах, взятых со всего открытого интернета. В процессе обучения (`training`) модель усваивает любую информацию, содержащуюся в обучающих данных. Когда промпт отправляется в LLM, есть надежда, что релевантная вопросу информация была включена в обучающие данные, в идеале — многократно.

К сожалению, большая часть информации не будет включена:

- компании хранят приватные базы данных;
- часть информации просто скрыта или трудно доступна;
- поскольку новости публикуются каждую минуту суток, всегда будет существовать информация, на которой LLM не была обучена.

## Ключевая идея: добавить информацию прямо в промпт

Вопрос тогда в том, как убедиться, что LLM знает эту полезную информацию. Короткий ответ: просто добавить её в промпт (`just put it in the prompt`).

Ключевая идея RAG-системы в том, что промпт можно модифицировать перед отправкой в большую языковую модель. В дополнение к исходному вопросу пользователя можно добавить информацию, которая помогает LLM ответить.

Если задать RAG-системе вопрос «почему отели в Ванкувере настолько дороги в эти выходные?», система сначала выполнит шаг retrieval, чтобы собрать релевантную информацию. Затем языковой модели предоставляется `augmented prompt` (дополненный промпт), включающий как исходный вопрос, так и любую извлечённую информацию. Теперь у LLM есть информация, необходимая для точного ответа.

## Retriever

Конечно, эту информацию нужно откуда-то извлечь. Компонент RAG-системы, который отвечает за этот процесс, называется `retriever`. Retriever управляет `knowledge base` доверенной, релевантной и, возможно, приватной информации. Когда RAG-система получает промпт, retriever находит и извлекает наиболее релевантную информацию из knowledge base, чтобы поделиться ею с LLM. Затем модель использует эту извлечённую информацию при формировании ответа на промпт.

Название Retrieval Augmented Generation (это, по общему признанию, «mouthful» — трудно произносимая фраза) теперь, надеюсь, обретает больше смысла: всё, что делается, — это улучшение или «дополнение» (augmenting) способа, которым LLM генерирует текст, посредством предварительного извлечения релевантной информации из knowledge base.
