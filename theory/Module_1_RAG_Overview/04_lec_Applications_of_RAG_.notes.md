## Общая модель применения RAG

Core idea of RAG: pair an off-the-shelf LLM with a knowledge base of information it might not have had access to when it was trained.

Many LLM-powered systems implement this model. Лекция перечисляет несколько областей применения.

## Code generation

Одна важная application of RAG is code generation.

Это значимо, потому что language models have been trained on lots of code, conceivably every public Git repository. Но generating correct code for a specific project requires specialized information.

LLM needs to know:

- classes in the project;
- functions;
- definitions;
- overall coding style being used.

RAG system can use your own code base as the knowledge base. Тогда LLM получает project-specific information.

Retriever может retrieve:

- relevant classes;
- definitions;
- files from the repository.

После этого LLM is much better able to:

- generate code relevant to your project;
- answer questions relevant to your project.

Слайды формулируют результат как improved code generation and Q&A, tailored to your actual repository.

## Company chatbots

Another major application is customizing chatbots to an individual company.

Every company has its own:

- products;
- policies;
- communication guidelines.

Enterprise documents can be treated as a knowledge base. Это позволяет deploy LLMs in a variety of useful ways.

### Customer service chatbot

Customer service chatbot can know information about:

- company products;
- current inventory;
- common troubleshooting steps.

### Internal chatbot

Internal chatbot can accurately answer questions about:

- company policies;
- useful documentation.

### Grounding company responses

In either case, the knowledge base helps ground the LLM’s responses in the company’s specific products or policies.

Это helps minimize cases where LLM generates generic or misleading responses.

Слайды уточняют примеры internal documents: manuals, support guides, FAQs.

## Healthcare and legal domains

RAG has significant applications in healthcare and legal domains.

В таких случаях knowledge base might contain:

- legal documents from a particular case;
- text from recently published medical journals;
- other niche and potentially private information.

В fields like these:

- precision is imperative;
- amount of niche information is vast;
- amount of potentially private information is vast.

RAG-based approach might be the only way to deploy an LLM-based product that is sufficiently accurate and uses private information.

Слайды формулируют это как high-impact domains, where RAG supports precision and privacy needs.

## AI-assisted web search

Another major application is AI-assisted web search.

Historically, search engines have worked like a retriever:

- given a search query;
- they return relevant websites.

Today search engines provide AI summaries of search results. Цель таких summaries: quickly present the most useful information in a skimmable way.

These AI web summaries are basically a RAG system whose knowledge base is the entire Internet.

На слайдах это описано как:

- search engines as retrievers;
- return websites for a given query;
- AI summarizes search results;
- RAG with the internet as a knowledge base;
- summaries powered by real-time retrieval.

## Personalized assistants

Large-scale RAG systems can be powerful, but highly personalized ones can also be powerful.

Personalized assistants can appear in:

- text messages;
- email client;
- word processor;
- calendar;
- other personal software.

They can help users:

- send messages;
- organize schedules;
- draft documents;
- complete projects big and small.

In each case, the more context the LLM has about the project, the better it can support that work.

## Personal knowledge base

For personalized assistants, the knowledge base might be relatively small.

Examples:

- text messages;
- contact lists;
- emails;
- a folder of documents.

These documents are dense with important context. Поэтому RAG system with access to small-scale personal information can complete tasks in a way that is significantly more relevant to what the user is doing.

Слайды резюмируют это как:

- your data is the knowledge base;
- LLM + your data;
- more context leads to better results.

## Общий вывод

RAG model has applicability in a wide variety of contexts.

Many companies, organizations, and individual users have collections of information that can enhance the quality of text generated by an LLM.

Whenever you have access to information that likely wasn’t used to train a large-language model, there is a potential for building a useful RAG application.

RAG might even allow LLMs to be used in contexts that were otherwise impossible.
