## Обзор трёх техник перед объединением

Это завершение обзора различных техник поиска и фильтрации, используемых внутри retriever, — далее рассматривается, как их можно использовать вместе как часть техники `hybrid search`, чтобы воспользоваться их разными сильными сторонами.

Краткое повторение того, как работает каждая техника, и её ключевые преимущества:

- **Metadata filtering** использует жёсткие критерии, хранящиеся в метаданных документа, чтобы сузить результаты поиска. Быстрый, простой в реализации и легко интерпретируемый подход. Возможно, сам по себе не является отличной техникой поиска, но обеспечивает строгий фильтр «да/нет», который не могут дать ни один из двух других подходов.
- **Keyword search** оценивает и ранжирует документы на основе наличия в них тех же keyword'ов, что и в промпте. По-прежнему довольно быстрый и простой в реализации подход, который может отлично справляться с поиском релевантных документов. Особенно хорошо работает в случаях, когда промпты и документы содержат технические ключевые слова или названия продуктов, поскольку в результатах будут именно эти точные слова. Однако keyword search опирается на точные совпадения, поэтому не способен извлекать документы со схожим смыслом, но другими словами.
- **Semantic search** оценивает и ранжирует документы на основе схожести их смысла с промптом. Документы и промпты вкладываются (embedded) как векторы, чьё расположение в пространстве отражает их смысл. Найти наиболее похожие документы означает найти документ, чей вектор-эмбеддинг ближе всего к вектору промпта. Semantic search медленнее и более вычислительно затратен, чем keyword search, но обеспечивает гибкость, которую не даёт ни одна другая техника поиска.

## Конвейер hybrid search

Поскольку у всех трёх подходов есть свои относительные сильные стороны, обычно их объединяют в единый конвейер hybrid search следующим образом:

1. Как всегда, промпт получает retriever.
2. Retriever выполняет для этого промпта и keyword search, и semantic search. Результат — два ранжированных списка документов: один получен и отранжирован с помощью keyword search, другой — с помощью semantic search. Например, каждая техника поиска может вернуть по 50 документов, причём многие документы будут присутствовать в обоих списках, но, возможно, в разном порядке.
3. Далее оба списка фильтруются с помощью metadata filter, чтобы убрать нерелевантные документы (например, фильтр может убрать документы, не относящиеся к работе конкретного пользователя). В примере из лекции после фильтрации в списке keyword search остаётся 35 документов, а в списке semantic search — только 30.
4. Теперь эти два ранжированных списка нужно объединить в единое ранжирование.

## Reciprocal Rank Fusion (RRF)

Часто используемый алгоритм для объединения таких рейтингов называется `reciprocal rank fusion` (RRF, взаимное слияние рангов). Этот алгоритм вознаграждает документы за высокое место в любом из списков, позволяя при этом контролировать, какому из рейтингов — keyword или semantic — придавать больший вес.

Формула reciprocal rank fusion:

> Score = 1 / (k + rank in list 1) + 1 / (k + rank in list 2) + … + 1 / (k + rank in list n)

Документы получают баллы на основе своей позиции в каждом списке. `k` — гиперпараметр; для начала предположим, что он равен нулю. В этом случае каждый документ получает баллы, равные обратной величине своей позиции в списке (reciprocal of their ranking): первое место даёт один балл, второе место — половину балла, и так далее. Документы набирают баллы из каждого ранжированного списка, и их суммарные баллы используются для расчёта итогового ранжирования.

Для retriever из примера это ровно два рейтинга — его keyword rank и semantic rank. Если документ оказался вторым в одном списке и десятым в другом, он наберёт 1/2, или половину балла, из первого рейтинга, и 1/10, или 0.1 балла, из второго, что в сумме даёт 0.6 балла. Эти баллы затем используются для повторного ранжирования (re-rank) всех документов.

### Параметр K

`K` используется для контроля влияния наивысшего ранжированного документа.

- Когда **K = 0**, документ, занявший первое место в любом списке, мгновенно взлетает на вершину общего ранжирования, даже если он высоко ранжирован лишь однажды. Например, документ с первым местом получает один балл, а документ с десятым местом — одну десятую — это десятикратная разница.
- Увеличение **K до, например, 50** сглаживает разницу. Теперь документ с первым местом получает 1/50 балла, а документ с десятым местом — 1/60, что даёт гораздо более скромную разницу в баллах. По-прежнему выгодно быть первым, но не настолько, чтобы это доминировало над рейтингами в любом другом списке.

Важно отметить, что RRF учитывает только ранг (позицию) документа в каждом списке, а не баллы, которые привели к этим позициям. Даже если документ, занявший первое место, набрал значительно больше баллов, чем второй, эта информация не учитывается алгоритмом RRF.

## Параметр Beta: вес keyword vs. semantic

Внутри retriever hybrid search обычно имеет второй гиперпараметр, называемый `beta`, который позволяет взвешивать рейтинги, полученные семантическим или ключевым поиском.

Например, можно установить beta = 0.8, отдавая 80% важности (веса) рейтингу от semantic search и только 20% — рейтингу от keyword search. Разбивка 70/30 (70% semantic, 30% keyword search) — обычно хорошая отправная точка, и это соотношение можно донастраивать под конкретную систему, чтобы понять, что работает лучше всего.

- Для приложений, где точное совпадение слов действительно важно, но при этом нужна некоторая семантическая схожесть, стоит взвешивать результаты keyword search сильнее, чем результаты semantic search.
- В других случаях, где важнее семантическое сходство, а keyword'ы менее критичны, стоит взвешивать результаты vector search (semantic search) сильнее, чем результаты keyword search.

## Возврат итоговых результатов

На этом этапе retriever уже готов вернуть свои результаты. В зависимости от того, сколько документов было изначально запрошено — это обычно называется `top K` (или `top_k`) — из итогового hybrid-рейтинга возвращаются наиболее похожие K документов.

## Итоги по hybrid search

Hybrid search позволяет retriever воспользоваться разными преимуществами, которые дают keyword search, semantic search и metadata filtering: keyword search обеспечивает точное совпадение слов, semantic search позволяет более гибкое сопоставление на основе смысла, а metadata filtering отфильтровывает документы по строгим критериям.

Существует немало возможностей изменять то, как работает эта гибридная система: будь то настройка параметров алгоритма BM25, выбор того, по каким метаданным фильтровать, или изменение весов keyword и semantic поиска на этапе reciprocal rank fusion.

Такой гибридный подход позволяет использовать сильные стороны каждого подхода и настраивать производительность системы под данные вашей knowledge base или под потребности конкретного проекта.

Чтобы проводить такую настройку, однако, нужен способ измерять, насколько хорошо работает retriever — этому посвящена следующая лекция об оценке (evaluation) retriever.
