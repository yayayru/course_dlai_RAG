# Обзор архитектуры retriever

## Общая ментальная модель системы

На протяжении модуля рассматриваются несколько разных техник поиска, но полезно иметь общую ментальную модель того, как устроена система в целом — высокоуровневый взгляд на архитектуру retriever и на то, как его компоненты работают вместе.

Когда RAG-система получает промпт, он сначала отправляется в retriever. Retriever имеет доступ к `knowledge base`, которую можно представлять просто как набор текстовых файлов в базе данных. Retriever должен быстро определить, какие документы наиболее релевантны промпту, и вернуть их, чтобы они были переданы в `LLM`.

## Две техники поиска

Большинство современных retriever используют в этом процессе две разные техники поиска:

- **Keyword search** (ключевой/лексический поиск) — более традиционный подход: retriever ищет документы, содержащие точные слова из промпта. Этот подход проверен временем и десятилетиями использовался в системах информационного поиска.
- **Semantic search** (семантический поиск) — retriever ищет документы, имеющие смысл, похожий на смысл промпта. Этот подход делает retriever более гибким, так как позволяет находить документы, релевантные промпту, даже если они не содержат точных слов, которые пользователь включил в свой промпт.

Каждая техника поиска возвращает набор документов — например, 20–50 документов от каждой. Обычно многие документы попадают в оба списка, но, поскольку стиль поиска различается, в одном списке они могут быть ранжированы выше, чем в другом.

## Metadata filtering

На этом этапе каждый список фильтруется на основе метаданных (`metadata filtering`). Например, некоторые документы в knowledge base могут быть релевантны сотрудникам инженерной команды, а другие — сотрудникам HR. Система знает, к какой команде принадлежит пользователь, и на этом этапе применяет фильтр по метаданным, чтобы дальше проходили только документы, релевантные соответствующему департаменту.

## Hybrid search: объединение результатов

После этого у retriever есть два отфильтрованных списка: один сформирован keyword search, другой — semantic search. Эти два списка объединяются, чтобы получить итоговое ранжирование наиболее релевантных документов. Retriever возвращает документы с наивысшим рейтингом из этого итогового списка — на этом извлечение (`retrieval`) завершено. Документы отправляются дальше, чтобы быть добавленными в `augmented prompt`.

Такой стиль поиска называется `hybrid search`, потому что он опирается на несколько техник для формирования итогового ранжирования документов.

## Вклад каждой техники

Каждая техника даёт свой вклад в общую эффективность retriever:

- **Keyword search** — обеспечивает чувствительность системы к точным словам, которые пользователь включил в промпт.
- **Semantic search** — даёт системе гибкость находить документы, смысл которых похож на промпт, даже если в них не используются те же слова.
- **Metadata filtering** — позволяет системе исключать документы на основе строгих критериев так, как не позволяет ни один из двух других подходов.

> Проектирование высокопроизводительного retriever означает понимание относительных сильных сторон каждой из этих техник и последующую настройку баланса между ними в соответствии с потребностями конкретного проекта.

Далее в модуле подробно разбирается каждая из трёх техник, начиная с самой простой — metadata filtering.
