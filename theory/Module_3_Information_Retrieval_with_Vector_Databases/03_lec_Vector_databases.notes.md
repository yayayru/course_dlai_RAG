## Что такое vector database

В production RAG-системе векторы обычно хранятся и извлекаются из специализированной базы данных, называемой `vector database`. `Vector database` — база данных, спроектированная с нуля для хранения высокоразмерных (high-dimensional) векторных данных и реализации векторно-ориентированных алгоритмов, таких как `Approximate Nearest Neighbors` (ANN), рассмотренный ранее.

Vector database стали популярны в начале 2020-х годов в ответ на широкую доступность больших языковых моделей и взрывной рост техник на основе vector embedding, таких как semantic search. Стандартные реляционные базы данных плохо справлялись с semantic search — их производительность была намного ближе к крайне неэффективному алгоритму K-Nearest Neighbors.

Vector database оптимизированы для таких задач, как построение proximity graph, который питает HNSW search, или вычисление векторных расстояний, поэтому они хорошо масштабируются и работают значительно быстрее в большинстве vector-based приложений, в частности — при построении RAG-системы.

## Weaviate

Vector database, которая используется в этом курсе, называется **Weaviate**. Это популярная open-source vector database, которую можно запускать как локально, так и в облаке. На рынке существует широкий спектр других vector database. Если для будущих проектов выбрана другая vector database, она почти наверняка предоставит очень похожую функциональность на ту, что демонстрируется здесь на примере Weaviate. Цель — получить практический опыт работы с воркфлоу, общими для любого RAG-проекта.

## Этапы подготовки vector database к поиску

Есть несколько шагов, необходимых для того, чтобы подготовить vector database к обработке поисковых запросов; некоторые из них обрабатываются автоматически:

1. настроить базу данных (`set up the database`);
2. загрузить документы (`load your documents`);
3. создать sparse vectors, которые будут обеспечивать keyword search;
4. создать dense embedding vectors, которые будут обеспечивать semantic search;
5. создать индекс, который будет обеспечивать работу ANN search algorithm, например, уже рассмотренный HNSW index.

После этого можно запускать реальные поисковые запросы. В следующей ungraded lab все эти шаги будут показаны подробно, но далее рассматривается несколько примеров того, как эти шаги реализуются в Weaviate.

## Работа с Weaviate: примеры

### Подключение и создание коллекции

Первый шаг работы с Weaviate — либо создание инстанса базы данных, либо подключение к уже существующему. Примеры того, как это делается, будут показаны в ungraded lab.

Далее нужно создать коллекцию (collection) для хранения данных. В примере создаётся коллекция под названием `article`, которая будет хранить заголовок (title) и текст (body) новостных статей. Код также указывает, что каждый тип данных будет `text`. Что более важно, этот вызов указывает, какая embedding-модель, или векторизатор (vectorizer), должна использоваться для создания семантических векторов для каждой добавляемой статьи.

### Добавление данных в коллекцию

После настройки коллекции она готова к добавлению данных. Данные добавляются в коллекцию с помощью метода `batch` этой коллекции. `Batch.addObject` фактически добавляет объект в коллекцию, но при этом также подсчитывает и отслеживает ошибки, что даёт возможность впоследствии их исправить или прервать цикл, если встречается слишком много ошибок.

### Векторный поиск (vector search)

Как только данные вставлены, можно выполнять векторный поиск. В первом примере запроса указывается коллекция, только что созданная, и затем передаётся текстовый запрос (text query). Также передаётся конкретный запрос метаданных, который возвращает расстояние (distance) — расстояние между вектором запроса и вектором объекта для каждого объекта.

### Keyword search

Можно также выполнять keyword search. Weaviate автоматически создаёт inverted index, который позволяет отобразить, какие слова используются и как часто, в каждом документе. Здесь можно выполнить простой BM25-запрос, изученный в прошлом модуле, и запросить топ-3 документа по рейтингу на основе этого запроса.

### Hybrid search

Можно также комбинировать vector search с keyword search в форме `hybrid search`. При hybrid search и keyword, и vector search выполняются параллельно в фоновом режиме, а затем, с помощью параметра `alpha` (который в примере установлен в 0.25), баллы vector search и keyword search взвешиваются соответствующим образом. Так, при alpha = 0.25 vector search получает вес 25%, а остальные 75% достаются keyword search. Результаты соответствующим образом переранжируются (re-ranked), и возвращаются топ-3.

В production и на практике именно это используется большинством компаний, поскольку это позволяет сбалансировать семантическое сходство vector search и строгое совпадение keyword search.

### Фильтрация (filters)

Поверх этого также можно применять фильтры (filters). Например, можно задать фильтр, который применяется к конкретному свойству (property) и проверяет значение этого свойства. Если оно совпадает, объект проходит фильтр и может быть возвращён. Если не совпадает — он не возвращается.

## Итоговый цикл работы

Весь цикл от начала до конца выглядит примерно так:

1. настраивается база данных;
2. затем загружаются и индексируются данные;
3. наконец, пишется конкретный запрос, включающий hybrid search и фильтры.

Это хороший обзор того, как использовать vector database. Ungraded lab даёт возможность на практике поработать со всеми этими шагами.
