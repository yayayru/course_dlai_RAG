## Конспект по коду

### Назначение

Ноутбук `C1M4_Ungraded_Lab_1.ipynb` (в репозитории фактически находится по пути `practice/Module4/ungraded_labs/ungraded_labs_1/C1M4_Ungraded_Lab_1.ipynb`) — необязательная (`ungraded`) лабораторная работа на тему исследования возможностей LLM. Задачи ноутбука:

1. Разработать функцию, которая позволяет LLM поддерживать связный контекст разговора (работать как chatbot).
2. Изучить, как различные параметры влияют на поведение и вывод LLM.

### Импорты и зависимости

- `json`, `random` — стандартные библиотеки.
- Из `utils` импортируются `generate_with_single_input` и `generate_with_multiple_input` — функции для вызова LLM.

### Вспомогательный файл `utils.py`

Содержит функции для вызова LLM через прокси DLAI (`https://proxy.dlai.link/coursera_proxy/together`, при отсутствии `TOGETHER_API_KEY` в окружении) либо напрямую через `together.Together`, если ключ `TOGETHER_API_KEY` задан:

- `get_proxy_url()`, `get_proxy_headers()`, `get_together_key()` — получение URL прокси и ключей API из переменных окружения.
- `generate_params_dict(prompt, temperature=None, role='user', top_p=None, max_tokens=500, model="Qwen/Qwen3.5-9B")` — формирует словарь параметров (`kwargs`) для последующего вызова LLM. Позволяет заранее собрать все параметры в одном месте, а затем передать их через `**kwargs`.
- `generate_with_single_input(prompt, role='user', top_p=None, temperature=None, max_tokens=500, model="Qwen/Qwen3.5-9B", together_api_key=None, **kwargs)` — отправляет одно сообщение LLM (формирует `payload` с полем `messages`, содержащим единственное сообщение) и возвращает словарь `{'role': ..., 'content': ...}` с ответом ассистента. Параметры `top_p`/`temperature` добавляются в payload только если они не `None` — иначе прокси/API получает свои значения по умолчанию.
- `generate_with_multiple_input(messages, top_p=None, temperature=None, max_tokens=500, model="Qwen/Qwen3.5-9B", together_api_key=None, **kwargs)` — аналогичная функция, но принимает список сообщений (`messages` в формате `{'role': ..., 'content': ...}`), что позволяет передавать историю разговора (контекст).
- `call_llm_with_context(prompt, context, role='user', **kwargs)` — добавляет новое сообщение пользователя в список `context`, вызывает `generate_with_multiple_input(context, **kwargs)`, затем добавляет ответ ассистента обратно в `context` и возвращает ответ. Используется для поддержания многоходового диалога.

Используемая по умолчанию модель — `Qwen/Qwen3.5-9B`.

### Раздел 2 — Recap on generation functions

#### 2.1 `generate_with_single_input` и `generate_with_multiple_input`

Демонстрируется базовый вызов `generate_with_single_input("Explain to me very briefly what is a Cyclotomic Polynomial. No more than 5 sentences.")` — LLM возвращает словарь `{'role': 'assistant', 'content': ...}` с определением циклотомического многочлена.

Далее показан вызов `generate_with_multiple_input` со списком сообщений `[system_dict, user_dict]`, где `system_dict = {"role": 'system', 'content': 'You are a very ironic, but helpful assistant.'}` — демонстрирует, что можно передавать `system`-сообщение, влияющее на тон ответа (в примере ответ получается ироничным).

Также показана передача параметров через `**kwargs`: `kwargs = {"prompt": ..., 'top_p': 0.7, 'temperature': 1.4, 'max_tokens': 100}`, затем `generate_with_single_input(**kwargs)` — демонстрирует более творческий вывод (стихотворение про летающего кролика) благодаря повышенным `top_p` и `temperature`.

#### 2.2 Генерация kwargs с нужными параметрами

Определяется функция `generate_params_dict(prompt, temperature=None, role='user', top_p=None, max_tokens=500, model="Qwen/Qwen3.5-9B")`, которая просто собирает переданные параметры в словарь `kwargs` и возвращает его — более гибкий подход, чем всегда прописывать параметры напрямую в функции генерации.

Пример использования: `kwargs = generate_params_dict("Solve 2x + 1 = 0.")`, затем `generate_with_single_input(**kwargs)` — LLM решает уравнение пошагово.

#### 2.3 Поддержание разговора (`call_llm_with_context`)

Определяется функция `call_llm_with_context(prompt, context, role='user', **kwargs)`:

1. Добавляет `{'role': role, 'content': prompt}` в список `context`.
2. Вызывает `generate_with_multiple_input(context, **kwargs)`.
3. Добавляет ответ LLM обратно в `context`.
4. Возвращает ответ.

Демонстрация: создаётся список `context` с `system`- и `assistant`-сообщениями, затем последовательно вызывается `call_llm_with_context` с разными промптами (*"Make a 2 sentence poem"*, затем *"Now add two more sentences."*) — показано, что LLM корректно продолжает предыдущий разговор, опираясь на накопленный `context`.

### Раздел 3 — Understanding the Parameters

#### 3.1 Введение

Объясняется теоретическая основа: входная последовательность токенизируется и векторизуется; эти векторы подаются в LLM, которая выдаёт вектор вероятностей (`probability vector`) — каждый индекс представляет вероятность выбора конкретного токена следующим. При `greedy decoding` модель выбирает токен с наибольшей вероятностью; этот токен добавляется к предложению, и процесс повторяется до достижения `max_tokens` или специального стоп-токена. `Greedy decoding` детерминирован — при одинаковом входе модель всегда даёт одинаковый выход, что снижает креативность. Для внесения случайности в ноутбуке рассматриваются четыре параметра: `top_p`, `top_k`, `repetition_penalty` и `temperature`.

#### 3.2 Nucleus Sampling — `top_p`

LLM конфигурируется на случайный выбор среди `p` наиболее вероятных токенов (по кумулятивной вероятности). Диапазон значений — от 0 до 1: `top_p = 0` даёт детерминированный результат (всегда самый вероятный токен), `top_p = 1` разрешает выбор любого токена с учётом распределения вероятностей.

Демонстрация на запросе *"In one sentence, explain to me what is RAG (Retrieval Augmented Generation)."*:

- При `top_p = 0`, три вызова подряд (`max_tokens = 500 + random.randint(1,200)` — используется, чтобы обойти систему кэширования) дают **идентичные** ответы.
- При `top_p = 0.8` три вызова дают **три разных** предложения — при этом первые несколько токенов часто совпадают (поскольку их вероятность очень высока), а далее ответы расходятся сильнее.

#### 3.3 Top-k sampling

LLM выбирает следующий токен из `k` наиболее вероятных вариантов. Меньшее `k` даёт более предсказуемые результаты (похоже на выбор наиболее вероятного токена), большее `k` — больше разнообразия.

Демонстрация: при `top_k = 0` три вызова дают идентичные ответы (совпадающие с результатом при `top_p = 0`); при `top_k = 10` — три разных, но связных ответа.

#### 3.4 Temperature

`temperature` — скалярное значение, контролирующее случайность предсказаний модели; в отличие от `top_p`, теоретически может принимать любое положительное значение (хотя провайдеры моделей иногда ограничивают верхний предел).

Формула корректировки вероятностей:

```
adjusted_probability(p_i) = exp(log(p_i) / temperature) / Σ exp(log(p_j) / temperature)
```

То есть: логарифм каждой вероятности делится на `temperature`, результат экспонируется, затем вероятности нормализуются, чтобы снова суммироваться в 1.

Эффекты разных значений `temperature`:

- **Низкая (<1)** — заостряет распределение вероятностей, усиливая детерминированность выбора.
- **Высокая (>1)** — сглаживает распределение, увеличивая случайность выбора токена.
- **= 1** — оставляет распределение без изменений (баланс креативности и детерминизма).

Важное замечание из ноутбука: `temperature = 1` **не** делает результат детерминированным — она лишь меняет форму распределения, но не ограничивает возможность выбора маловероятных токенов на дальнем конце распределения. Только `temperature = 0` (либо `top_p`/`top_k = 0`) гарантирует детерминизм.

Числовой пример из ноутбука для исходного вектора `[0.6, 0.3, 0.1]`:

- `temperature = 0.5` (низкая) → `[0.77, 0.18, 0.05]` — самая высокая вероятность увеличивается, самая низкая — уменьшается.
- `temperature = 1` (нейтральная) → `[0.6, 0.3, 0.1]` — без изменений.
- `temperature = 2` (высокая) → `[0.49, 0.27, 0.24]` — распределение более плоское.

Демонстрация на запросе про RAG с `temperature ∈ {0.3, 1.5, 3}`:

- При `temperature = 0.3` — связный, точный ответ.
- При `temperature = 1.5` — тоже связный, чуть более вариативный ответ.
- При `temperature = 3` — совершенно бессмысленный вывод (смесь случайных слов на разных языках, символов), причём заметно более длинный текст — при высокой `temperature` вероятность стоп-токена становится сопоставимой с вероятностью любого другого токена, поэтому модель реже останавливается естественным образом и чаще упирается в лимит `max_tokens`.

Далее демонстрируется совместное использование `temperature` и `top_p` на запросе *"Write a small poem about a flying rabbit."* с параметрами `(temperature=0.3, top_p=0.8)`, `(1.5, 0.5)`, `(3, 0.05)`:

- При `(0.3, 0.8)` и `(1.5, 0.5)` — оба ответа связные стихотворения (второй — более необычный/творческий, но не бессмысленный), поскольку `top_p` сужает пул возможных токенов даже при повышенной `temperature`.
- При `(3, 0.05)` — несмотря на низкий `top_p`, очень высокая `temperature` делает результат частично бессмысленным, хотя менее бессвязным, чем без `top_p` вовсе — модель почти всегда выбирает реальные слова, но конструкция предложений теряет смысл.

Вывод ноутбука: обычно `temperature` и `top_p` задаются вместе — `temperature` регулирует форму распределения вероятностей, а `top_p` ограничивает набор возможных токенов, что вместе управляет случайностью и предотвращает потерю связности текста.

#### 3.5 Repetition penalty

`repetition_penalty` снижает вероятность уже использованных моделью слов, что стимулирует использование нового словаря — полезно для повествования (`storytelling`) или диалогов, где повторяющийся язык звучит монотонно.

Демонстрация на запросе *"List healthy breakfast options."* с `repetition_penalty ∈ {None, 1.2, 2}` (максимальные значения выводятся как `{0.3, 1.5, 3}` из-за опечатки в коде цикла вывода, но фактически переданные модели значения — `None, 1.2, 2`): все три ответа связные и структурированные списки вариантов завтрака, разбитые по категориям (быстрые/горячие/низкоуглеводные и т.д.). Отмечается, что слишком высокий `repetition_penalty` может сделать текст бессмысленным, так как модель избегает повторения даже естественно повторяющихся слов (предлогов, артиклей), из-за чего может выбирать неподходящие слова.

### Раздел 4 — Bonus: Creating a Simple Chatbot

Необязательный (не входит в оценивание) раздел, демонстрирующий построение простого чат-бота без применения объектно-ориентированного подхода (в учебных целях, не для production).

- `print_response(response)` — форматированный вывод сообщения с ANSI-цветами: роль `assistant` выводится зелёным, `user` — синим.
- `chat(temperature=None, top_k=None, top_p=None, repetition_penalty=None)` — запускает интерактивный цикл общения: печатает стартовое сообщение ассистента, затем в цикле считывает ввод пользователя через `input()` (выход по слову `'STOP'`), вызывает `call_llm_with_context` с указанными параметрами сэмплирования, добавляет сообщения пользователя и ассистента в `context` и печатает их через `print_response`.

Пример запуска: задаются `system_prompt` («ты дружелюбный и смешной ассистент, добавляющий юмор») и `assistant_prompt` (приветствие), формируется `context = [system_prompt, assistant_prompt]`, затем вызывается `chat()`. В приведённом выводе ноутбука виден только первый обмен репликами (пользователь написал «Привет»), полноценный диалог не зафиксирован в выводе, так как чат интерактивен.
